## mlv-app/launch-site-census-per-site-whole-repo-1
rule: a census of the launch sites a live-reference guard must see classifies SITES, not files, reads the whole repo, and reads them from the language's own parser, never a hand-written tokenizer. Every site that starts PowerShell from base64 or detaches a process, in any tracked *.ps1 / *.psm1, is listed per site (path, a pinned substring of the site text, an expected count per file) with the reason the guard still sees it; a second site in a classified file, or a pinned site that moved or vanished, fails like a new file. Sites are every CommandAst of the PowerShell AST at any depth (script blocks, `$()` in expandable strings, `&&` / `||` chains, if/else branches, pipelines), so two launches in one statement are two sites. Encoded: a pwsh / powershell or `&` / `.` command carrying a switch pwsh's own CLI resolves to -EncodedCommand (-ec, or any prefix of encodedcommand; a one-letter -e on a target not known to be pwsh only beside a pwsh-only switch), or a quoted argv element / command-line string with that switch near pwsh context. Detached: Start-Process / saps / start with WindowStyle Hidden in any form Start-Process binds (space, colon, any prefix from its own parameter table, a splatted hashtable literal or member assignment), or Win32_Process Create. Every quoted string that mentions a launch word is parsed as code too, and a string that is executed ([scriptblock]::Create, .AddScript, iex, pwsh -Command) but built at run time is an `unresolved` site that fails until classified. Bounds: PowerShell scripts only; paths containing `/test` (all of tools/testing/**) and file names starting with `test` are excluded as tests, and so is the guard; variable flow is followed only within one file (a string handed in from another file is scanned where it is a literal); System.Diagnostics.Process / ProcessStartInfo launches (CreateNoWindow, a ProcessStartInfo WindowStyle) are not a detached shape.
mechanism: 2026-10-24 reviews of PR #665 and of #669 r1-r2. The first census walked two roots and keyed a file-level found-set, so a second launch in a classified file kept the same set, and its single-line Start-Process pattern missed a hidden launch split over backtick continuations. Three rounds of a Python tokenizer (statements, quotes, here-strings, comments) each closed the named counterexamples and each review found new holes in the same tokenizer: one-statement if/else and `A && B` pairs, launches inside `$()` in a string, a quoted `;` in an executed here-string, `& $exe -EncodedCommand`, a `$()` quote desync behind a quoted '<#'. Reading sites from Parser::ParseInput closed all of them at once. The whole-repo walk surfaced the wake helper, the closeout dashboard, a build smoke probe and the venue probes, and the AST read surfaced 9 executed strings built at run time (build-guard's fragment, venue smoke and capture commands, runspace share reads); none starts a PowerShell driver that holds a lane worktree.
